## 照片

- 数组顺序就是画廊顺序；`move` 不改 ID。每张照片有自己的页面 `/photos/<id>/`（见下文 Phantom）；旧的单张链接 `/photos/#photo-p16` 仍在画廊里打开快速预览，预览里有到照片页的入口。
- `featured: true` 的照片进雪山 Photography 营地的三张小图和旧首页精选，至少保留一张。
- `add` 生成网页母版（长边 ≤ 3200px，无元数据），不保存相机原片。所有修改命令都支持 `--dry-run`。
- 工具运行时持有 `.cache/photos.lock`；进程异常退出后，确认没有照片命令在跑再删掉它。
- 构建用 `sharp` 生成 320–1920 共六档宽度的 AVIF 和 WebP，外加一份 1920 宽 JPEG（无 JS 时的链接和"Open image"目标）。编码结果缓存在 `.cache/images`，CI 也会复用。
- AVIF 质量 60 是对照 WebP 测过 PSNR 后定的：每张都不低于 WebP，体积约小两成。调参数前先做同样的对比。

## 粒子图案

素材放 `image/`（PNG 或 JPG，亮且不透明的区域会变成粒子），在 `site.json` 的 `phantom.shapes` 中登记。构建时会缩到 900px 以内并压缩，原图不必预先处理。

## 山（首页 /）

首页是一个用 WebGL2 画的雪山目录页：打开时镜头绕山缓慢旋转，滚轮、点击、方向键或手机上下滑动，镜头沿螺旋小径一站一站爬到峰顶；整座山跟访客的本地时间走，越往高处天色越深。它以前在 `/mountain/`，那个地址现在是一张转向页（`noindex`，用一小段脚本带上 `#营地` 跳到 `/#营地`，没有脚本时 meta refresh 到首页）。其他页面的主导航是 Home、Photography、The Phantom、Guestbook；分享链接时的预览图是 `src/mountain/social.jpg`（1200×630，用 `?debug&clean` 渲染截取），山形或配色大改后重截一张。

- 文案和营地在 `content/mountain.json`：`intro` 是标题屏，`camps` 按山脚到峰顶排列（3–9 个，最后一个是峰顶）。每个营地有 `id`（也是 `#id` 深链接）、`title`、`description`，可选 `kicker`、`href`（站内路径或 `https://*.g3rry.com/`，缺省时显示 "Trail under construction"）、`model`（营地的主题模型，见下）。
- 主题模型（`props.js`）：`trailhead` 路标、背包和篝火；`photography` 三脚架相机和一排晾着的照片，颜色取自精选照片里最鲜艳的色调（构建时算）；`phantom` 一圈立石，上方的光点平时散着飘，到站时聚成 `site.json` 第一个 Phantom 图案（构建时从 `image/` 取点），鼠标划过会被冲散；`mailboxes` 一排信箱和一盏灯；`summit` 峰顶旗、发光的登顶簿和一串三角旗，旗数等于留言板已公开的留言数（运行时读 `/api/guestbook`，最多 12 面）。峰顶卡片同时显示最新一条留言，Photography 卡片显示三张精选照片。
- 代码在 `src/mountain/`，原生 ES module，无运行时依赖：`terrain.js` 生成山体、营地位置、小径、树和云，`refine.js` 细化山体网格，`detail.js` 散布谷底的云杉、阔叶树、灌木和石块；`camera.js` 定每站机位和转场；`renderer.js` + `shaders.js` 负责渲染（阴影、雾、天空、云、泛光）；`palettes.js` 是一天里几个时刻的配色关键帧；`weather.js` + `weather-shaders.js` 是云海以下的天气（见下）；`beyond*.js` 是主路线之外的两个章节，`audio.js` 是声音（都见下）；`sky-menu.js` 是天空菜单，`globe.js` 是自由视角里的地球仪（见下）；`props.js` 是帐篷、旗和各营地的主题模型；`scene.js` 把这些组装起来，`worker.js` 在后台线程里跑它（不支持模块 Worker 时退回主线程）；`main.js` 管交互和状态。没有多重采样的低画质档（手机）在合成时做 FXAA 抗锯齿。不支持 WebGL2 时页面显示营地列表，背后铺分享图。
- 时间与天气（`weather.js` + `weather-shaders.js`）：整座山只有一个时钟，云上云下都跟它走。
  - **时刻**是访客的本地时间（或天空菜单里设的时间）。日出日落随季节，南半球时区月份倒过来。
  - **日月的位置**由 `heavens(hour, light)` 算：太阳一天绕一圈，正午最高（方位 `SOUTH`、高度 `HIGH`），日出日落时在地平线上，夜里在山下；月亮是满月，始终在太阳对面、略高一点，所以总有一个在天上。背景里的太阳圆盘和月亮就画在这两个方向上。
  - **光照和天色**由 `skyPalette(sky, thin)` 给出：颜色在 `palettes.js` 的关键帧之间按时刻过渡（夜、拂晓、上午、正午、黄金时刻、黄昏），主光来自在天上的那一个；晨昏之间主光从一侧经头顶换到另一侧，那时它本来就最弱。
  - **高处的空气变稀**（`thin`，二号营地以下为 0，峰顶为 1，`main.js` 的 `thinAt`）：天顶和地平线逐渐变暗；过了一半以后星星和极光才出来（`dark`），白天的极光减半。照在雪上的光仍然是当时的日光或月光。这是对时钟唯一的艺术处理：峰顶任何时刻都是星空和极光，但光线照样随时间变。白天暗天空下的雪会过曝，所以曝光随之收一档（`glare`）。
  - **天气只在云海以下**（`DECK`，高度表约 1,700 m，过渡带上下约 200 m）：`clear` / `cloud` / `fog` / `rain` / `storm` / `snow`。云海的云团随云量增减，阴天光线变漫射、天色变灰，雨天地面变暗、有雨丝和雨幕，雪天朝上的面积雪、树冠挂雪，雾天谷底是一片雾海，夜里有零星灯火（不落在河里）。水面在云海以下也取谷底的天色和光照。爬过 Camp II 后天气的效果逐渐淡出。
  - **雾海的顶不是平的**（`weather-shaders.js` 的 `lowAir`）：顶面随地面起伏（`bank`，上下约 0.6 个单位），否则镜头正好在雾顶高度时（雾天的登山口），雾顶会变成一条横贯画面的直线。云海以上的云从云下看时被遮住的程度也在过渡带里渐变（`lowCloud` 的 `behind`），不在云海高度一刀切，不然跨在那个高度上的云会排出一条横纹。
  - **山自己的云**（山脚的云团和高处的几缕，`terrain.js` 的 `scatterClouds`）也随天气多少：`amounts()` 里的 `sea`，晴天只留约一成的几缕，阴雨雪天全在。种子小的那些留得最久（`weather-shaders.js` 的 `deckPuff`）。
  - **全阴天从云下看**（`uGloom`）：天空整片是谷底的灰（`overhead()`，月亮也被遮住），云海以上的云看不见，云海的底面是暗灰；从云海上方往下看，云顶仍是当时的日光或月光。地平线以下露出的天空取谷底的雾色，所以从高处看远处地面的边缘不会有一道硬线。
  - **雷暴**（`storm`，夏季才有）：比大雨更暗、全阴。`createStorm()` 每隔几秒在谷底随机一处落雷：一道从云底到地面的闪电（`boltSegments` 生成折线和一两条分叉，`boltVertex` 画成朝向镜头的发光条），闪光照亮周围的云、地面、雨丝和谷底的天空（`uFlash`，离落点越近越亮），一次一到两闪，间隔不少于 0.4 秒；"减少动态效果"时没有闪电，只有一次缓慢的亮起。雷声是录音，按距离延迟（`main.js`），近处是炸雷，远处是低闷的滚雷（见声音）。调试：`strike()` 立刻落雷，`strike(.8)` 把闪光定在 0.8 方便截图，`strike(.8, [x, z])` 指定落点。
  - 天气按本地日期确定（刷新不变，按月份取概率），由 `weatherFor(date)` 返回 `{ kind, intensity }`，以后接真实天气只换这一个函数。原有的雪粒子在云海以下由天气接手；"减少动态效果"时雨变成慢速短点。
  - 营地不再有各自的时辰：`mountain.json` 里的 `time` 字段和 `palettes.js` 里开场、Moonward 专用的配色都已删除。改某个时刻的颜色就改对应的关键帧。
- 天空菜单（`sky-menu.js`）：右上角高度表旁的读数（山上的时间、云海以下的天气和一个小日晷）打开它。时间改的是整座山的光照和日月位置，天气只影响云海以下。
  - **打开时**：
    - 菜单占用营地卡片的位置，不加任何底框。
    - 在营地间打开时，镜头穿过云海降到瀑布对面的河谷（`camera.js` 的 `valleyPose`，`main.js` 里的 `VALLEY` 站；它不在滚轮经过的站点序列里，编号 −3，−2 是山之心）。
    - 背后加一层更深的暗影，因为正午的雪或雾会把谷底照得很亮。
    - 小径的灯点会隐去。
  - **控件**：
    - 时间是一个星盘式的表盘：正午在顶部，实线是今天日出到日落的弧，虚点是夜里那段；地平线上立着一座小山。拖动太阳（夜里是月亮）或用方向键都能调；手调了别的时间时，边上有一个灯色短刻度标出访客的真实时间。
    - 天气是五种天空的列表，并标出今天本来的那种；`Light`–`Heavy` 滑杆调强度。
    - 标题用一句话描述此刻的谷底，例如 "Heavy rain / in the small hours."。
    - "Follow my clock" 让太阳滑回真实时间，并恢复当天的天气。
    - 手调的天气约一秒内过渡（`conditions().set(kind, intensity, true)`），`?debug` 里的调用仍然立即生效。
  - **关闭**：Done 或 Escape 回到打开前那一站（从山之心里打开的话，会先出洞到河谷，Done 再进洞）；滚轮或滑动会直接离开山谷去爬山。穿山的那几秒里读数按钮不响应。
  - **和声音的关系**：环境声读的是同一份谷底天气，所以在菜单里选了雨，镜头在云海以下就能听到雨声。
  - **首访提示**：头两次访问时，读数下垂下一条引线，旁边一句说明（`localStorage` 的 `g3.sky.cue`）；打开过菜单后不再出现。
- 自由视角（菜单里的 Free camera）：
  - **轨道**：镜头绕山轴上一点（`ORBIT`）转，限定距离和仰角，拉远压低就能到云海以下。
  - **操作**：拖动画面转向，滚轮或双指缩放，也可以用方向键和 +/−。
  - **地球仪**（`globe.js`）：随视角一起转，里面画着低多边形的山、各营地、云海那一圈和镜头位置；拖地球仪和拖画面效果一样。旁边显示方位、仰角和距离。
  - **进入时**：配色回到首页的那套，路线点和开场文字隐去。
  - **退出**：Back to the trail 或 Escape 回到首页远景。
- 构建把整个目录连同两款 OFL 字体（`@fontsource` 的 Cormorant Garamond、JetBrains Mono 拉丁子集）按内容哈希发布到 `/assets/mountain-<hash>/`，所以模块之间的相对 import 不用改。
- 网格精度：`terrain.js` 的环形网格之上，`refine.js` 先把紧挨山脊和尖峰的顶点挪到脊线和峰尖上（只挪离得最近的那个，不超过半格，网格不会翻折），再把面片明显偏离高度函数的格子细分一级（山脊算足，沟槽只算一部分，否则面会变暗），镜头附近太粗的谷底格子也细分；粗细格子之间用扇形过渡，不留裂缝。网格可疑处还会取格子中心，让对角线顺着山脊走、不横切。颜色仍按原网格决定，细分和吸附只改变光影，不会多出雪斑。参数在 `QUALITY.refine`（`tolerance` 越小细分越多）。改完先看待机画面里山脊和加载线是否贴合，再用 `?debug` 的 `bench()` 看帧时间。
- 谷底细节：`detail.js` 在松树之外散布林缘的云杉、草甸上成片的阔叶树、成丛的灌木和石块（悬崖下的碎石坡最密，草甸上零星几块大石），都避开营地、小径和已有的树，数量上限在 `QUALITY.detail`。它们和松树共用一个着色器，`aPart` 区分树皮、针叶、阔叶和岩石；每棵树的高矮也按种子略有不同。以后哪里要空出地面（比如溪流），在 `detail.js` 的 `open()` 里加一条判断即可。
- 山的形状是确定的：同一份代码每次生成同一座山。改 `terrain.js` 里的 `PEAKS` 和噪声参数会整体改变山形和营地位置；远景里那几座独立的远山在 `FAR_PEAKS`。小径是在山体网格上按坡度寻路得出的，陡处自动走之字形，营地之间改了位置会自己重新找路。
- 水（`water.js` 定形状并生成网格，`water-shaders.js`、`water-renderer.js` 负责画）：融雪小溪从登山口右上方的雪线顺冲沟流下，在约 2 个单位高的崖口跌进山脚的深潭，河从潭口出来，在登山口前面绕过山脚，再穿过平原、从远山的缺口流向天边。水道是高度函数的一部分（`terrain.height()` 先由 `water.carve()` 下切，再铺营地平台），网格怎么采样都带着河道、崖壁和潭；寻路把水当作不可走（`buildTrail` 的 `avoid`），树也不长在水里。水位只降不升，贴着沿途最低的地面；靠近山脚只切窄岸，不碰山体和营地，开场天际线和各站机位不变。水面是逐面平涂的三角形：颜色取当前时辰的天色（深处偏天顶色，按菲涅尔反射天空），面片随波翻动；岸边和瀑布脚下整片三角形泛白并向下游移动。白水（溪流的陡段和瀑布）不反射天空，按哑光、略透光的表面打光（`water-shaders.js` 的 `whiteWater`），比雪略暗，不会在泛光里发亮。瀑布是一整条封闭的分面水柱：横截面是前凸后平的椭圆，始终垂直于下落轨迹（出崖口时平、往下渐竖），所以从侧面、上方看都有厚度；泡沫条纹按整块面片顺流下滑，落点有一圈起伏的低多边形水花和淡淡的水雾。潭四周的崖壁按方位起伏（`pool.edge`），瀑布正下方保持原样，好和溪流接上。溪流比低档地形网格的格子还窄，所以整体抬高一点（`STREAM_LIFT`），地形不会盖住水。改走向就改 `water.js` 顶部的极坐标控制点，改完确认小径不过水、登山口高度不变。`hide('water')` 只隐藏水，用来对比耗时。
- 加载：页面一出现就是黑底，中间一条细线从屏幕两侧向峰顶爬，画的正是开场镜头里山的天际线（主峰加远山；`scripts/mountain-ridge.mjs` 在构建时按 `camera.js` 的 `FOV`、待机机位和营地数描出，营地的平台和页面上一样切进地形，竖屏、横屏各一条，结果和图片编码一起缓存在 `.cache/images`）。线的进度跟着真实步骤走：模块就绪、Worker 建好场景、着色器编译完（驱动支持 `KHR_parallel_shader_compile` 时和场景构建并行）、第一帧画出；两步之间缓慢前移，不会停住。右上角高度表同步从 0 数到开场高度。加载再快，最后一段也用 0.6–1.2 秒画完，不会一下跳满。画到峰顶时峰顶亮起一盏灯，在此之前画面保持全黑、开场镜头停在起点；随后山在这条线下浮现（1.6 s），线停留 0.7 s 后淡出，镜头的环绕从静止用 2.5 s 加速到正常，所以淡出时线和山脊始终对得上。加载期间页面不会跳动：文字一开始就在最终位置（"Scroll or click to climb" 按钮先占位、上线后淡入），两款字体用 `font-display: block` 且已预载，不会先显示较宽的后备字体再换掉；带 `#营地` 打开时加载期间不显示首页文字。改了山形、机位或视场角，构建会自动重描。
- 进入营地页：卡片的 "Enter"、回车、再点一次当前营地，或 Photography 卡片里的小图，都先用营地自己的转场把画面收成全黑再跳转（光圈 / 光点 / 信封 / 帐篷，见下文"转场与刘海屏"）；到站后会预取该营地的页面，黑场通常很短。画面盖满后山停止渲染，把机器让给下一页；按返回键回来时接着动。
- 支线章节（`beyond.js` 建模，`beyond-shaders.js`、`beyond-renderer.js` 负责画）：主路线之外还有两站，写在 `content/mountain.json` 的 `beyond` 里（`below` 山之心、`above` Moonward；字段同营地，另有 `pending`（没有 `href` 时卡片上那行字）和 `below.eras`（0–8，山之心保存的"年代"数））。山之心现在通向 `/eras/`（历代页面），`eras` 是 8，对应那里的八个年代。删掉某一项，页面上就没有那一站，对应的模型也不生成。
  - **山之心（The Heart，`#heart`）。** 瀑布旁、朝登山口那一侧的崖壁上有一座石门（两块立石加盖石，门洞里悬着一枚发光的金色碎晶，门槛上长着几簇冷色晶体），和营地的道具一起画，位置由 `placeCave()` 沿潭壁算出；门前的树和灌木会被清掉。洞内是另一个独立的小场景：一枚由多根晶体组成的"心"悬在静水上，按 2.6 s 一拍（两下）搏动，光沿晶体和岩壁向外传；`eras` 枚不同色的小晶体绕着它转，岩壁上同样数量的青色光脉一圈圈环绕（每一条代表 `/eras/` 里的一个年代；那边增减年代时改 `eras`）。池面是真实的镜像（整个洞腔倒过来画一遍在水面下，再盖一层水面），洞顶的水滴会在池面荡开涟漪，点一下池面也会。洞内外互不可见：镜头进出都穿过黑场（`main.js` 里 `travel.through`），所以洞腔不需要和山体对得上。
  - **Moonward（`#moonward`）。** 越过峰顶，镜头彻底离开这座山，飞到月球背面回望。画面里不再有山，所以月球和山不会被放在一起比大小。
    - **路线**（`camera.js` 的 `planFlight`，出发时规划一次）：从出发时的机位向前，贴着峰顶的山脊越过去（离旗杆约两个单位），然后在背面保持高度平飞，脚下的山坡落下去，速度渐渐起来；月亮从前方的地平线下升起来时，镜头抬起、直奔月亮，越来越快，从它边上掠过，绕到背面减速入轨，最后才转头看向来处。路径是穿过几个点的向心 Catmull-Rom 曲线（不打结、不过冲），按弧长走，每个点到达的时刻由一条单调三次曲线决定（`timing`），所以速度连续变化、没有顿挫；镜头看向路径前方一段（速度越快看得越远），再转向月亮，最后转向家园，方向之间按向量插值。世界在镜头离开山脊、开始爬升时才变暗（`state.sky` 在 0.36–0.6 之间），所以掠过山脊那段看得见地面。视角在最快那段略微变宽。整段 6.4 秒，不可打断；"减少动态效果"时是一次淡入淡出。
    - **去的是哪个月亮**（`main.js` 的 `aimFrom`）：天上的月亮如果升着，并且在镜头越过峰顶时转得过去的方向上（左右 100° 以内），就飞向它，它一直在原处，不动也不淡出（太高时按同一方位、70° 高度去）。否则（在镜头背后，或白天在地平线下）这次飞行有自己的月亮：在峰顶前方，起先在地平线下，镜头爬升时它从地平线上一点点升起来，像是地平线在往下落（`rise`，0.13–0.46；月亮着色器在 `uOrbAir` 时把地平线以下的部分挡掉）；它从不淡入，白天是一轮淡月。天上原来那个在镜头背后、看不见的时候淡出（`stay`）。月球、家园和那串星点都按这个方向重新摆放（`beyond-renderer.js` 的 `aim()`）。
    - **回程**不是倒放，5.6 秒：离开月球背面时看着家园，所有的转向都在山还没出现时做完：在远处、从侧面绕一个大弯（不从峰顶正上方经过，那样看着它会让画面翻转），绕到要回的那个机位的视线后方；山出现时（`state.sky` 在 0.42–0.6 之间回来）镜头已经对准那个机位的方向，之后只是沿视线直直滑进去、减速停下，不再转。家园那颗小星球留到山重新出现才消失；飞行自己的月亮在下降时落回地平线下。
    - **到位画面**（`spacePose`）：镜头在月球背面上方 0.3 个月球半径处，月平线是一道横过画面下部的圆弧，家园（原来山所在的位置上一颗小星球，峰顶那盏灯还亮着）悬在月平线上方，一串星点从它向左上方划过天空，就是来时的路。太阳的方向是固定的（`spaceMoon().light`）：月夜的边界从画面中间穿过，文字压在暗的一侧，另一侧每个环形山都拖着长影。月面在镜头下缓慢滑过，像在环月轨道上。
    - **月亮和家园不是网格**，是逐像素求出的精确球体（`beyond-shaders.js` 的 `orbHit`、`moonFragment`、`homeFragment`）：每个像素的视线和球求交，边缘是真正的圆，近看远看一样锐利，并写入深度让山能挡住它。
    - **月面**是一条规则：五种尺寸的环形山，每种尺寸在球体里铺一层格子，但只有两三成的格子里有坑，坑在格子里的位置随意，所以不会排成行；坑沿不是正圆，随方位起伏；每个坑有"年龄"：大多数是老坑，浅、坑沿低而宽，少数是新坑，深、坑沿锐利，大的有平底，周围有一圈带条纹的浅色抛射物。整体还有一层缓慢的起伏。坡度是解析算出来的，所以光影干净。小到不足几个像素的那几档自动略去；手机档略去最细的一档。暗色的月海上环形山更浅。
    - **从山上看的月亮**：它本来就是满月（和太阳相对），按满月打光（光从镜头身后略偏左来），用月壤的反射规律（Lommel-Seeliger）而不是普通的漫反射，所以满月边缘不发暗、看到的是明暗斑块而不是坑的立体感；它隔着大气：越低越暗、越偏暖（蓝光先被吸收），斑纹淡一些，边缘软约两个像素；周围只有一圈紧贴的柔光和很淡的大光晕，低处偏暖。亮度按当前曝光补偿，白天峰顶暗天空下也不会发灰。到了月球附近换成固定的太阳，光从满月慢慢转到侧光（`phase`），月面上才出现长影。
    - **高度表**在途中从米换成千米，一路数到 384,400 km；卡片上显示的也是这个距离。山之心和 Moonward 之间不能直达：先回到开场远景，再自动接着走（`onward`）。在 Moonward 点家园那颗小星球可以回到峰顶。
  - **怎么去。** 右侧路线两端各多一个标记（线上方一弯月牙、线下方一枚菱形，用几个点和主线隔开），点它、点山上的石门或月亮、或者打开 `/#heart`、`/#moonward` 都直接过去。滚轮、方向键和滑动也能到，但要两次：在开场画面往回滚（或在峰顶继续往上）第一次只是"叫"它一下（底部出现一行提示、标记闪烁、石门或星路亮起），4.5 秒内再来一次才出发。这样顺着主路线滚到头的人不会被带走，想去的人不用找入口。在支线站点里和营地一样：有 `href` 时出现 "Enter"（转场是 `geode` / `eclipse`），没有时显示 `pending` 那行字。
- 声音（`audio.js`）：全部是录音，不再合成（唯一的例外是瀑布），默认关闭；右下角（手机在左上角名字下面）的开关打开后记在 `localStorage`（`g3-sound`、`g3-theme`、`g3-volume`），`M` 键也能开关。打开后旁边是两个选项（I Piano：钢琴加环境声；II Nature：只有环境声）和音量滑条（`setVolume`，0–1，按感知曲线换算，默认 0.75）。浏览器只允许在点击或按键之后出声，所以记住的"开"要等第一次触碰才开始。录音放在 `content/sound/`（来源和许可在那里的 `CREDITS.md`：音乐是公有领域的钢琴录音，环境声是 CC0），构建时每个文件单独按内容哈希（`/assets/sound/名字-哈希.mp3`），名字到地址的对照表写在 `#mountain-sound` 的 `data-sounds` 里；只有用到时才下载。两层，互不借用音色：
  - **音乐**：每类地方一首独奏钢琴（`PIECES`）：山上是萨蒂《第一号吉姆诺佩迪》，山之心是肖邦 E 小调夜曲（Op. 72 No. 1），Moonward 是肖邦"竖琴"练习曲（Op. 25 No. 1）。用 `<audio>` 流式播放、经过 Web Audio 的推子和低通（`track`），一首放完停约 7 秒再从头开始；离开再回来接着原处放。换地方时一首让给另一首（`turn`）：进出山之心是岩石把旧的一首闷住、淡出，镜头穿过后新的一首起来；去 Moonward 时旧的一首在低通里慢慢合上（像空气在身后合拢）、新的从闷住的状态打开，整个过程在 6.4 秒的飞行里；回程反过来，快一些。第一次开声音时三首都被"启动再停下"一次（`prime`），有的浏览器只允许这样启动过的媒体在之后自己开始播放。
  - **环境声**跟着镜头走，都是真实录音（`bed`：两个声部从录音的随机位置交替播放、交叉淡化，所以听不出循环）：风（亚利桑那 Kitt Peak 山顶的灌木丛，越高、移动越快越大、越亮，山之心里和太空中没有）；谷底下雨（或雷暴）时能听到雨，小雨一份，大雨在上面再叠一份更密的；雷暴时雷声按距离延迟（`main.js`），近处是一声炸雷，远处是低闷的滚雷，并按距离去掉高频。瀑布是唯一在这里合成的声音（低沉的轰鸣，`falls()`，按距离和左右方位）。地面的声音（瀑布、雨、雷）在 Camp III 以上听不到：爬山时按进度从 Camp II 渐弱到刚过 Camp III 为零，自由视角里按高度，去月球时也没有（`main.js` 的 `groundHeard` → `listener` 的 `ground`）。没有篝火声。
  - **没有音效**：点击、悬停、出发、到站、转场都不发声，移动时只是风变大。只有两件事有声音：雷（见上），和在山之心里点水面时的一滴水（水池自己落下的水滴只看得见、不出声）。
  - 调音量在 `audio.js` 顶部的 `LEVEL`（每个录音实测的均方根，统一换算到同一电平）和 `listener` 里各层的系数。检查时不用靠耳朵：`createAudio({ context, sounds })` 接受一个 `OfflineAudioContext`（这时音乐解码后播放而不是流式），`advance(秒)` 把环境声写到那一刻，渲染后算电平。目前（音量 0.75，A 计权）：钢琴约 −31 dB；风在低处约 −49、高处移动时约 −38；小雨约 −41、大雨约 −32；近雷峰值约 0.94、远雷约 −42；瀑布在 3 个单位处约 −32。去 Moonward 时两首交接处最多掉约 8 dB、一秒内回来，没有空档。页面被转场盖住或切到后台时声音淡出并暂停音乐。
- 调试参数：`?debug` 暴露 `window.mountain`（`station(i)` 跳到第 i 站、`chapter('heart')` / `chapter('moonward')` 直接到支线、`look(eye, target)` 任意机位（`look()` 撤销）、`pose()`、`time('dusk')`、`weather('rain', .8)` / `weather()`、`strike()`（见雷暴）、`seek(t)` 把正在进行的转场跳到第 t（0–1）处截图、`hour(22.5)` / `hour()`、`menu()` / `menu(false)` 打开或关上天空菜单、`orbit(方位°, 仰角°, 距离)` 直接进入自由视角的某一点（`orbit()` 回到小径）、`bench()` 测每帧耗时、`hide('bloom')`（`hide('weather')` 关掉天气，`'curtains'`、`'lights'` 单独关雨幕和灯火，`'moon'` 关月亮）、`notes(n, note)` 模拟留言板数据、`pointer(x, y)` 模拟指针、`sound` 是音频对象）；`?clean` 隐藏文字层；`?timer` 用定时器驱动渲染（后台标签页不跑 requestAnimationFrame 时用）；`?quality=low|high`；`?motion=reduce`；`?weather=clear|cloud|fog|rain|storm|snow` 和 `?hour=0..24`（可带小数）固定谷底的天气和时间，截图（包括重截分享图）时带上，结果才可复现。
## 转场与刘海屏

- **转场。** `src/veil.js` 以普通脚本放在每个页面的 `<head>` 里（第一次绘制前就运行，也负责给 `<html>` 加 `js` 类）。山上进入营地时调用 `g3veil.leave({ effect, href, origin })`：画面按效果收成全黑，再跳转，并在 `sessionStorage` 里记下效果；目标页从第一帧起就是黑的（`veil.css` 的 `html.veil-hold`），等页面准备好再用同一个效果打开。普通页面等字体和首图解码；`<html data-veil-wait>` 的页面（实验页、照片页）等引擎发出 `g3:ready`（首帧之后）。各种情况都有上限（1.8 s / 3.5 s），脚本出错时黑场 4 s 后也会自己撤掉。系统开了"减少动态效果"时一律改成短暂淡入淡出。
- **效果与营地的对应**在 `src/mountain/main.js` 的 `VEILS`：`photography` 七叶光圈（相机），`phantom` 光点从点击处扩散成金点再变黑，`mailboxes` 信封折起、盖上金色火漆（去外站，只有离场），`summit` 和其他营地是帐篷门（离场时拉链从上往下拉上，到站时从地面往上拉开、两片门帘向两边分开）；两个支线章节是 `geode`（九片不规则的岩片向中间一点金光合拢）和 `eclipse`（天色变暗，月面从右上滑到正中，边缘一圈日冕，最后一粒光珠熄灭）。效果画在一张 2D 画布上，新效果加在 `veil.js` 的 `effects` 里，`time` 是 [离场, 进场] 毫秒。调效果时在控制台用 `g3veil.still('iris', .6)` 定格任意一帧，`g3veil.clear()` 撤掉。
- **样式。** `veil.css` 由构建追加到每个页面的样式表末尾（`styles.css`、山和实验页的 CSS），不单独请求。
- **刘海和下巴。** 所有页面都是 `viewport-fit=cover`，文字和按钮用 `env(safe-area-inset-*)` 避开刘海、圆角和底部横条。手机 Safari（iOS 26 起）遇到贴着屏幕边缘的 `position: fixed` 元素，会在状态栏和工具栏下面填一条纯色，这就是上下两条"不可用边框"的来源。所以山的画布不再是 fixed：它放在一个不滚动的页面里、高 `100lvh`，浏览器就把山画到状态栏和工具栏下面。浏览器自己必须填色的地方（状态栏、Android 的 `theme-color`、回弹区）跟着画面顶边的天色走：渲染器每隔一段时间把顶边四个像素异步读回（`renderer.js` 的 `sampleEdge`，不阻塞 GPU），`main.js` 写进 `--tint` 和 `theme-color`。实验页的画布仍是 fixed，但它的底色和页面同为 `#06080b`，填色看不出来。真机效果只能在手机上确认，桌面浏览器的模拟器没有刘海。

## Phantom 实验页（/phantom/）与照片页（/photos/<id>/）

两种页面共用一套引擎 `src/phantom/`（原生 WebGL2，无依赖；构建时整个目录按内容取哈希输出到 `assets/phantom-<hash>/`），文案与参数在 `content/phantom.json`。引擎按页面里有哪些 `data-chapter` 段落装配章节，每页的 `lab-config` 只带本页要显示的内容。

- **实验页**（`src/phantom/page.html`）介绍技术，每章一个例子：`example.develop` 是 Develop 的示例照片，`example.atlas` 是 Atlas 示例经过的 stop。
- **照片页**（`src/phantom/photo.html`，每张照片一页）只有 02 Develop 和 03 Atlas。Atlas 的路线由构建自动选：照片有自己的 stop 时是「地球 → 城市俯瞰 → 机位」；同一地点（`place` 相同）另有已解算的 stop 时，借用那个机位看街景、不放那张照片，太阳按本张的拍摄时刻；否则只到城市俯瞰。所在城市不是 `live` 时没有 Atlas。
- 每张照片都必须有 `photos` 元数据和深度模型（`scenes.json` + `scenes/<id>.bin`），否则构建失败。
- **翻页方式（节拍）。** 有 WebGL 时页面不滚动，和首页的山一样一站一站走：每章由若干「拍」组成（`main.js` 里各章的 `beats()`，每拍有进度 `p`、名字和行程秒数），一次滚轮手势、一次上下滑动、一次方向键 / 翻页键 / 空格走一拍，镜头用定好的时长走完然后停住。滚轮按手势计：180 ms 内不断的一串事件算一次，触控板的惯性不会多翻；同一串里再拨一次（增量衰减后又跳起，或者反向）也认；持续滚动最多每 550 ms 一拍。右侧标尺每拍一格、按章分组，点击可直达；当前拍的名字在左下读数里。顶部导航和 `#ignite` 这类地址到该章第一拍，地址栏跟着章节走。进入一章时从头播放它的开场，倒退进入时直接回到那一拍；Atlas 里向前跨站从该站开头飞入，向后跨站直接切回。最后一拍 `end` 是页脚，粒子回到开场的光环。没有 WebGL 时仍是普通的长文页面。

| 章节 | 内容 | 数据 |
| --- | --- | --- |
| Ignite | 旧首页粒子小实验的 GPU 版，指针力场、点击冲击波、长曝光快门 | `site.json` 的 `phantom.shapes` |

  - 旧金山那批比太平洋时间快 3 小时，只用 p16 的阳光核对过，精度在十几分钟以内。

- 新地点（如田纳西）：先用 `npm run photos -- add` 把照片加进画廊，在 `photos` 里补 EXIF；再在 `sites` 里填 `origin` 和 `lidar`，在 `atlas.stops` 里加 stop，然后跑 `lidar` 与 `frames`。

  - 分类错了的结构用 `structures` 走廊改正：2010 年金门测量把大桥归成了植被，走廊内 40 m 以上的点改成桥（class 17，金色），抽稀时整体保留。
  - 以山地为主的点云用 `terrain` 提亮地面和植被。
- stop 的写法：
  - `kind: "globe"` 让地球转到该地点。
  - `kind: "overview"` 是俯瞰，`orbit` 用米写方位、仰角和距离。
  - 其余是照片 stop。`approach` 决定镜头怎么到达机位：`orbit` 绕主体，`above` 从上方，`below` 穿过街面（LiDAR 看不到的地下），`previous` 从上一站直接飞来（`arc` 是航线拱起的高度）。
  - `exposure` 是曝光补偿（EV），用于点稀疏的长焦近景。
  - `project: false` 表示只显示照片、不投影。
  - `photos: [...]` 显示一排照片，用于记不清具体位置的那组。
- 机位 `vantage` 有两种写法：「目标点 + 方位 + 距离」，或「位置 + 方位角 + 俯仰」，`subject` 是主体距离，也是对焦距离。
  - Liberty 由太阳方位和雕像的角大小解出。
  - 金门三张用后方交会解出：从点云里取塔顶、Salesforce 和 Transamerica 塔顶的三维位置，配上照片里的像素位置求相机位姿。p16 的解落在 Marshall's Beach 沙面上，p17、p18 落在 Conzelman Road。
- 拍摄时刻的光：
  - 构建时由 EXIF 和行程的时钟修正算出每个 stop 的拍摄时间（UTC，存进 `light`），页面用 NOAA 算法求太阳方位和高度（含大气折射）。
  - 太阳方向的阴影贴图贴合当前点云，被照到的点偏暖，处在阴影里的点偏冷，太阳本身也画在它真实的方向上。
  - 镜头到站的过程中，太阳从拍摄前两小时走到按下快门那一刻；俯瞰段先用下一张照片拍摄前两小时的光。
  - 取景器显示太阳的方位、高度和当地时间。
- 页面数据：点云约 15 MiB（六块），深度图约 4 MiB（18 张）；每块只在用到时才下载。

### 照片的深度模型（scenes.json）

网络只给相对深度，形状对，但没有尺度，远近之间还会弯曲。每张照片的深度模型由三部分锚点定出真实距离：

- 读照片写下的场景模型：
  - `subject` 是对焦距离。
  - `anchors` 是已知距离的点或框，例如一个 1.7 m 的人在画面里占多高。
  - `ground` 是地平面：地平线在画面两侧的位置，镜头离地多高，取样区域。
  - `far` 是天空所在的远限。
  - `note` 显示在 Develop 里。
- 解出机位的照片另有 `lidar`（atlas stop 的 id）：从机位看 LiDAR 得到的距离。`lidarRegion` 限定可信区域（沙滩和水会变，桥不会）。
- 拟合方法：
  - 先用单调曲线把相对深度映射到对数深度。
  - 再解一个边缘感知的最小二乘修正：沿颜色和深度的边缘断开，所以悬崖和沙滩各自按各自的锚点修正。
  - 最后把深度边缘对齐到照片的颜色边缘。
- 改了场景模型就重跑 `node depth.mjs <id>`。工具会报告各锚点的误差，并在 `.cache/phantom-scenes/<id>.jpg` 写出带锚点的深度预览，靠这张图判断模型是否合理。
- 地平线和镜头高度的读法：
  - 镜头在人眼高度时，行人的头都落在地平线上。
  - 镜头更低时，近处人物的脚和远处人物的脚之间的关系能同时解出地平线和镜头高度。
  - 积水里的倒影属于地面，不在地面下方。

## 其他年代（/eras/）

同一个站按八个过去的年份各重做一遍：1996、1999、2003、2007、2011、2014、2018、2023，每个版本只用那一年真有的技术，内容来自同一份数据（照片、地点、EXIF、留言板实时读取）。入口是 `/eras/`（全站页脚 "Other years"），它在 sitemap 里；各年份的页面都带 `noindex`。

- 文案在 `content/eras.json`：每年的 `name`、`line`（目录上的一句话）、`colophon`（"How it was built" 的段落），`dial: true` 的年份在目录上有 "Arrive by modem"。年份必须递增，且每年都要有对应的生成模块。
- `versions` 是站点自己的真实版本，排在重做的年份之后：2025 是旧首页 `/legacy/`，2026 是现在的首页（雪山）`/`。年份环从 2026 绕回 1996，各年代页上的 Time Ring 都用年份标注，不写 "Now"。
- 生成：`scripts/eras/index.mjs` 依次调用 `scripts/eras/y<年份>.mjs`，每个模块写自己年份的页面和图片到 `dist/eras/<年份>/`；`src/eras/<年份>/` 里的脚本和样式原样复制（文件名不加哈希，查看源代码本身就是内容的一部分）。照片的派生图走和主站相同的 `.cache/images` 缓存。
- 早期年份的图都是代码画的：`scripts/eras/pixels.mjs` 是 5×7 点阵字体和 GIF/PNG 输出（标题、88×31 小徽章、施工路障、计数器数字、Phantom 动图）；`scripts/eras/fonts.mjs` 把 @fontsource 的 WOFF 解包成 TTF，供 sharp 渲染 2007 年的光泽 logo（sharp 读不了 WOFF，直接传会静默换成默认字体）。
- 调制解调器：`src/eras/modem.js` 是作用于 `/eras/` 的 Service Worker，只放慢 1996 和 1999 两年：一条共享的线、最多四个连接、每个响应前 250 ms，速率按"连接速度 ÷ 8 × 0.85"。默认 1996 是 28.8k、1999 是 56K（按 48,000 bps 计）；访客在 `/eras/dialup.html` 或页脚菜单里换速度，设置存在 Cache Storage。拨号音是 `dialup.js` 用 Web Audio 现场合成的。
- 内容安全策略不变：所有年代都没有内联脚本或内联样式，"当年会写成 onMouseOver 属性"的东西都改成外部脚本挂事件。早期年份的 HTML 用大写标签，`check.mjs` 的正则因此全部不区分大小写。
- 访客计数器（1996、1999）请求 `/api/counter`（hunt Worker，见下文"解谜"），接口不通时计数器保持隐藏。
- 检查：每年都要有 `index.html`，目录要链接到每一年，年代页都带 `noindex`，年代脚本里不许出现 `innerHTML` 之类把留言文字当 HTML 的写法。
- 加一个年份：在 `eras.json` 里按顺序加一项，写 `scripts/eras/y<年份>.mjs` 并在 `index.mjs` 的 `builders` 里登记，静态文件放 `src/eras/<年份>/`。各年份页面里的 "Time ring" 会自动接上前后年份。

## 发布

`main` 受 [pages.yml](../.github/workflows/pages.yml) 管理：

- 向 `main` 发 PR：只构建和检查。
- 推送或合并到 `main`：构建、检查、测试通过后部署到 GitHub Pages。
- 每年 1 月 1 日自动重建一次，让页脚年份更新。
- 回滚：`git revert` 对应提交再推送，同一流程重新发布。

工作流中的官方 Actions 固定到提交 SHA；升级时核对 release 与 SHA。依赖升级同时更新 `package.json` 和 `package-lock.json`。

## 域名与 Cloudflare

- 域名在 Cloudflare Registrar 注册（自动续费，DNSSEC 由 Cloudflare 管理），DNS 由 Cloudflare 托管并代理到 GitHub Pages；`CNAME` 由构建按 `site.json` 的 `url` 生成。
- HTTPS 跳转、HSTS、缓存规则和 robots.txt 的 AI 爬虫设置都在 Cloudflare 后台，不在仓库里。
